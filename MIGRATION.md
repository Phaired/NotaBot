# Migration notes: Lua/discordia → TypeScript/discord.js

This document tracks how the Lua bot maps onto this TypeScript codebase, the state of
the port, and what still needs doing before this can replace the running bot. This
branch replaces the Lua bot in place: the TypeScript project lives at the repo root and
the original `.lua` files were removed (they remain in git history / upstream branches).

## Runtime / library mapping

| Lua bot | TypeScript |
| --- | --- |
| Luvit runtime | Node.js 20+ |
| discordia | discord.js v14 |
| coroutine-based async (`coroutine.wrap`, implicit yields) | `async`/`await` |
| `require('coro-http')` | global `fetch` |
| `require('json')` + `io.open` | `JSON` + `fs/promises` (`src/core/storage.ts`) |
| `config.lua` | `.env` (`src/config.ts`) |
| global `Bot` / `Module` / `Client` tables | `Bot` singleton + `BotModule` base class |
| prefix commands only | prefix **and** slash commands from one definition |

## Known gaps / deliberate changes

- **Not runtime-tested.** The port is verified to compile (`pnpm typecheck`) but has
  not been connected to a live Discord gateway. Treat every module as needing a
  functional smoke test.
- **Emoji dataset.** The unicode name↔codepoint table from `data_emoji.lua` is bundled
  as `assets/emoji.json` (3842 emoji, generated by `src/scripts/convertEmoji.ts`), so
  both unicode-name resolution (`:smile:`) and custom guild emoji work out of the box.
- **Localization.** The `localization/*.lua` tables aren't converted; the bot falls
  back to English (keys are printf-formatted as-is). To restore i18n, convert each
  `localization/<lang>.lua` into `localization/<lang>.json` of shape
  `{ "Locs": { "KEY": "..." } }`. Language-specific duration formatting uses the
  English formatter for now.
- **Owner `exec` / `load` commands dropped.** They loaded arbitrary Lua files at
  runtime; modules are now statically compiled, so `enable`/`disable`/`reload`/
  `unload`/`reloadconfig` remain but `exec`/`load` do not.
- **`message.content` for prefix commands** requires the privileged *Message Content*
  intent (already enabled in `src/core/client.ts`); slash commands don't need it.
- **Update/voice events now pass `(old, new)`** instead of a single object — see the
  event table in `FRAMEWORK.md`. Voice join/leave is derived from voice-state deltas.

## Verification checklist before going live

1. `pnpm typecheck` passes (CI gate).
2. Fill `.env`, run `pnpm dev`, confirm login + `Bot ready — N commands, M modules`.
3. `pnpm deploy-commands` (or automatic on boot) registers slash commands.
4. Smoke-test each module's commands via both `!cmd` and `/cmd`.
5. Verify persistence: change a config, restart, confirm it survived (`data/`).
6. Review every `TODO(port)` and the moderation-critical modules (`ban`, `mute`,
   `raid`, `modo`, `warn`) especially carefully.
